# dsh-pocket 安全改造设计讨论

【最后更新时间】2026-09-01

## 目标

- 基于已有插件[shaobeichen/dsh-pocket](https://github.com/shaobeichen/dsh-pocket)改造一个安全优先的手机公网访问DSH的新插件。
- 同一部手机可以绑定任意设备（比如访问公司电脑和家里电脑上的 DSH）
- 公司内外统一通过固定 HTTPS 入口访问，不再同时维护局域网与公网两套入口。
- 入口只允许由对应宿主电脑本机批准过的设备访问。
- 首次验证可以严格；验证完成后的日常使用应尽量方便。
- 安全方案应集成到 dsh-pocket，保持代码和长期维护简单可靠。
- 改造应具备通用性，完成后考虑向 dsh-pocket 上游提交 PR，使其他用户也能使用；不得硬编码用户自己的账号、域名、设备或基础设施。
- 暂不把公司网络监控作为方案约束；公司当前没有明确的相关监管限制。

## 用户使用流程

1. 用户在电脑上安装插件，并配置一个固定 Cloudflare 网址；插件不获取 Cloudflare 账号密码。
2. 用户只能在电脑本机发起“添加设备”，电脑显示短时、一次性的配对二维码。
3. 手机扫码后填写设备名称和一个至少 6 位的自定义密码，提交申请，再由电脑端人工批准；全程在浏览器内完成，不依赖系统指纹、Google 服务或手机 App。
4. 获准手机以后通过该电脑的固定网址访问；首次进入、新会话或页面退到后台超过 10 分钟后返回时，输入该设备的密码。
5. 页面持续打开和正常刷新时不重复打扰；关闭页面、切后台或锁屏都会停止前台续期，连续无前台活动满 10 分钟后会话失效。
6. 手机或浏览器不再使用、忘记密码时，只能在对应电脑本机删除该设备并重新配对；现有登录立即失效。

## 已确认决策

- 宿主范围：公司电脑与家里电脑都要支持。
- 客户端范围：主要由用户自己的同一部手机访问两台宿主。
- 当前阶段：新认证代码与自动测试已完成，尚未重新部署到 DSH Desktop，也未完成荣耀 50 新方案真实验收。
- 上游兼容策略：安全边界优先，危险访问模式直接删除，不为兼容现有行为而保留旁路；接受这可能降低破坏性改动 PR 的合并概率。
- 实施与贡献策略：允许重写为自己的安全分支，先自用验证；之后可提交代码 PR，也可只向上游提交完整 idea、威胁模型和实现方案，由开发者选择接受、部分采用或自行重写。
- 设计优先级：安全第一，方便第二。
- 手机端形态：纯浏览器是硬约束，不要求安装手机 App；原定纯 Passkey/WebAuthn 方案因中国 Android/国产 ROM 的实际兼容性不足（2026-09-01 荣耀 50 实测任一浏览器均无“此设备”选项，参考站 passkeys.io 同样失败，属系统级平台认证器不可用），认证方案改为“设备凭据＋每设备独立密码”，不再依赖 WebAuthn。
- 认证目标：指纹、密码、手机系统 PIN 等都不是必须形式；可以不依赖手机自带 PIN，核心要求是确保实际安全，并让中国用户能够正常使用。
- 独立认证边界：手机已经解锁仍不足以访问 DSH；每次进入 DSH 前必须再完成一次 Pocket 独立认证，目标类似银行 App 的独立登录认证。
- 独立认证形式：用户在扫码配对时提交一个自定义密码，允许数字、字母和符号，长度 6–256 个字符；电脑本机记录申请并批准后，后续访问使用该密码。电脑端只保存带随机盐的慢哈希验证值，不保存、回显或找回明文密码；登录同时要求浏览器持有对应设备凭据，密码泄露不能让未配对浏览器登录。
- 密码作用范围：每台已批准设备分别设置和保存自己的密码验证值；系统不提供修改或重置原设备密码。用户可以自行给不同设备设置相同密码，但系统不强制共享。
- 密码猜测防护：按设备累计计数：第 1–4 次输错可立即重试；第 5 次输错后等待 5 分钟，第 10 次后等待 15 分钟，第 15 次后等待 45 分钟，第 20 次及以后每累计 5 次输错等待 24 小时。输入正确后失败次数和等待状态全部清零。失败计数与等待截止时间必须持久化，重启 DSH 不能绕过。
- 密码恢复：不提供远程找回、重置原设备密码、邮箱、短信、验证码或恢复码旁路；忘记设备密码后，只能在电脑本机删除该设备，再按新设备完成完整配对和批准流程。配对申请中电脑只显示设备信息，不显示或保存明文密码。
- 设备粒度：设备凭据以浏览器实例为单位；同一手机的每个浏览器需各自配对并设置密码，清除浏览数据或更换浏览器后需重新配对；不依赖 Google/Apple 账号同步迁移凭据。
- 网络入口：删除独立 LAN 模式；公司内外统一走固定 HTTPS 公网入口，不保留普通 LAN HTTP、Host 分类、LAN 免密或 `0.0.0.0` 局域网监听。
- 身份模型：不建立用户名/账号系统；每台已批准设备由设备凭据＋设备密码构成身份，凭据可命名、查看和撤销。
- 凭据恢复：不提供远程找回；浏览器凭据丢失后，只能在对应宿主电脑的本机设置页重新配对。
- 宿主隔离：公司电脑与家里电脑分别独立配对和保存设备凭据与密码，不同步白名单、凭据或会话。
- 访问入口：手机分别保存“公司 DSH”和“家里 DSH”两个固定网址，不建立统一中转入口。
- 日常验证：首次进入或连续无前台活动满 10 分钟后，要求输入该设备的 Pocket 密码；正常刷新和页面持续在前台使用时不重复认证。网页无法可靠识别真正关闭，因此统一按服务端最后一次前台活动计时，不设置长期登录会话。
- 首次授权：电脑本机生成一次性二维码，手机扫码提出申请，电脑端显示申请后必须再手动确认“允许”才加入白名单；二维码本身不能直接授予权限。
- 固定网址配置：每台电脑由用户在 Cloudflare 建好固定网址并粘贴一次所需凭据；插件不负责 Cloudflare 账号登录或自动创建域名。
- 验证边界：插件自身维护和验证设备凭据白名单；Cloudflare 只提供固定 HTTPS 入口，不强制依赖 Cloudflare Access 账号登录。
- 本机管理：新增/删除手机、查看或修改公网入口凭据等安全设置只允许在宿主电脑本机操作。
- 远程权限：手机验证通过后可以完整使用 DSH；新增/删除设备、修改公网入口、查看相关凭据等 Pocket 安全设置仍只允许在宿主电脑本机操作。

## 技术实现基线（业界常用方案，AI 决定）

依据 2026-09-01 攻击者视角评审（独立子代理完成，来源含 MDN Cookies、W3C WebCrypto 规范、WebKit Bug 308718、OWASP 会话管理/认证/口令存储 Cheat Sheet、NIST SP 800-63B、Cloudflare 官方文档）：

- 设备凭据：`__Host-` 前缀长期随机 Cookie（CSPRNG ≥256 位），`Secure; HttpOnly; SameSite=Strict; Path=/`，服务端只存 SHA-256 哈希；每次完整登录（密码验证成功）轮换；含凭据的响应一律 `Cache-Control: no-store`。评审结论：与 WebCrypto 设备密钥方案在各攻击面等价，实现复杂度更低，对国产浏览器内核兼容性最好。
- 会话：会话 Cookie 无 `Max-Age`；超时判定只在服务端（空闲 10 分钟触发重认证）；页面隐藏时暂停轮询，保证“无活动”在服务端真实成立；登录成功时重新生成会话 ID；`visibilitychange` 只做 UX 预提示。
- 密码存储：固定使用 `argon2@0.45.1` 的 Argon2id `m=19456 KiB/t=2/p=1`，每次哈希自动生成独立随机盐；原生实现使用常数时间比较；未知设备做等价 dummy 验证抹平时序；错误消息统一，不区分“设备不存在/密码错误/正在等待”。
- 密码规则：允许数字、字母和符号，长度 6–256 个字符。记录残余风险：NIST SP 800-63B 对多因子场景建议至少 8 位；6 位纯数字密码在服务器数据库泄露且遭离线破解的场景下可能被穷举（Argon2id 可拖慢但不能阻止）。
- 猜测防护：计数按设备累计并持久化（严格按第 5/10/15/20 次绝对计数，等待期间不增加计数）；公开登录端点另按来源限制 30 次/分钟。接受持有有效设备 token 的攻击者可触发最长 24 小时等待的 DoS 残余风险。
- 配对：token 为 CSPRNG 256 位、TTL 5 分钟、置于 URL fragment（不进服务器与 CDN 日志）、首次提交即消费（无论批准与否）；同一时刻只允许一个待批准申请，出现新申请时拒绝新申请并保留原申请；手机提交后可关闭页面，电脑批准后返回配对页点击根路径入口按钮；电脑批准界面显示设备名与提交时间；配对提交端点按来源限制为 10 次/5 分钟。
- 传输与页面：公网浏览器到 Cloudflare 使用 HTTPS，Cloudflare Tunnel 到宿主使用加密隧道，宿主本机段仅为 `127.0.0.1` HTTP；认证页面开启 HSTS，CSP 禁止内联脚本和 `object-src`，并禁止 iframe。XSS 防护是第一优先防线：无论 Cookie 还是密钥方案，页面内脚本滥用都不可防。
- 已知边界（评审确认，任何纯浏览器方案均无法越过）：同源 XSS、手机本机特权访问（root/恶意软件/复制浏览器数据）、信任根在电脑批准端；对应恢复手段即“电脑删除设备后重新配对”。

## 已核实技术来源

- OWASP Password Storage Cheat Sheet：Argon2id 最低参数 `m=19456 (19 MiB), t=2, p=1`。https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#argon2id
- `node-argon2` README：当前版本以 Node.js 22 为测试基线，列出 Windows Server 2022 x64、Ubuntu 22.04 x64/arm64、Alpine Linux x64/arm64 预编译支持。https://github.com/ranisalt/node-argon2#before-installing
- `argon2@0.45.1` npm 包清单：实际包含 `prebuilds/win32-x64`、Linux glibc/musl x64/arm64 原生文件。https://unpkg.com/argon2@0.45.1/?meta
- Node.js Node-API 文档：Node-API ABI 跨 Node 主版本稳定，Node-API 8 支持 Node 16 及后续版本。https://nodejs.org/api/n-api.html
- MDN `Set-Cookie`：`__Host-` Cookie 要求 `Secure`、`Path=/` 且不能设置 `Domain`。https://developer.mozilla.org/docs/Web/HTTP/Headers/Set-Cookie
